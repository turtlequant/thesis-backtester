# 结构化投研设计

## 定位

结构化投研以同一套算子和分层框架完成三类任务：

1. **个股分析**：针对一只股票执行完整章节 DAG。
2. **最新研判**：从已保存的数值筛选策略取得当前候选，再批量执行同一框架。
3. **框架验证**：在多个历史截面重复执行筛选与框架，检验定性判断相对纯筛选是否产生增量效果。

分析路径由框架预先确定。Agent 负责在章节内部调用数据、组织证据和生成结构化输出，不决定下一步跑什么，也不在运行中改变 DAG。

## 当前分析与严格历史验证

| | 个股分析 / 最新研判 | 框架验证 |
|---|---|---|
| 分析时点 | 当前或用户指定的最新可用时点 | 冻结的历史截面 |
| 候选来源 | 单股输入或已保存的筛选策略 | 每个历史截面重新运行筛选策略 |
| 数据 | 当前 Provider 快照，可按需使用 AKShare 市场上下文 | 当前 Provider 在截止日之前已可得的数据 |
| 公司身份 | 正常展示 | 可按框架配置隐藏，减少先验偏差 |
| 算子 | 用户可见 v2 算子 | 同一框架；当前型算子切换为等输出契约的内部历史实现 |
| 输出 | 个股报告、结构化结论、批量汇总 | 多持有期收益、胜率、基准与框架增量效果 |

两种模式共享框架和输出契约，但不共享越界数据。历史验证没有安全等价实现时会在启动前失败，不会跳过算子或调用当前新闻。

## 使用方式

```powershell
# 桌面窗口，也可同时用本机浏览器访问日志中的地址
uv run python -m src.desktop.main

# 单股 CLI 分析
uv run python -m src.engine.launcher workspace/strategies/v6_enhanced/strategy.yaml live-analyze 601288.SH
```

桌面端是主要使用入口，CLI 用于自动化和调试。二者复用相同引擎资产。

## 个股分析流程

```text
选择股票与框架 → 确认分析时点 → 构建快照
→ 校验并拓扑排序章节 → 分批执行章节
→ 综合研判 → 保存 Markdown 报告与结构化结果
```

每个章节的执行步骤：

1. 解析该章节引用的多个算子。
2. 合并算子正文、允许的数据类型和输出 Schema。
3. 注入截止日、股票快照和前置章节输出。
4. Agent 在回合上限内调用受控查询工具并返回正文与结构化 JSON。
5. 校验和保存输出，作为后续章节的只读上下文。

核心财务输入不完整、算子缺失或结构化输出不可恢复时，应明确失败并保留诊断信息，不能生成看似完整的正式报告。

## 最新研判流程

```text
选择筛选策略 + 框架 + 数量
→ 预览候选、章节、任务量与预计消耗
→ 冻结策略/数据截面/框架
→ 批量执行个股分析 → 聚合排序与报告
```

- 定性投研只单向引用截面筛选的策略和候选。
- 并发数只影响吞吐，不改变股票、章节顺序和结果归属。
- 任务可在安全批次边界暂停，并从已完成的个股之后继续。
- 预览用于暴露 Agent 的工作范围，避免在对象、框架或成本不明确时直接运行。

## 框架验证流程

```text
选择筛选策略 + 框架 + 历史参数
→ 预览截面数、候选数、章节和算子边界
→ 每期运行数值筛选 → 构建历史快照
→ 执行历史安全的同契约框架
→ 采集前向收益 → 汇总增量效果
```

验证至少区分：

- 市场基准；
- 纯筛选候选池等权结果；
- 框架给出买入判断的组合；
- 框架高分组；
- 框架层相对纯筛选层的增量收益与胜率。

这项功能验证的是“结构化框架是否有用”，不是把某次自然语言报告机械回测。

## 数据边界

### Provider 选择

- **BaoStock**：免费历史基线，可维护行情、复权、估值和其能力范围内的财务数据。
- **Tushare**：凭 Token 使用的完整历史研究来源，独立维护自己的 SQLite 数据库。
- **AKShare**：当前即时上下文来源，不作为严格历史数据基线。

当前分析使用用户选定的数据口径；Provider 之间不会自动补齐。详细规则见 [数据层设计](data_layer.md)。

### 市场上下文

当前分析可按需查询新闻、资金、指数和行业上下文。这类信息不预先全部注入提示，以控制上下文规模；Agent 只有在相关算子允许时才能调用。

框架验证会用内部历史实现替代依赖当前上下文的算子，并核对输出字段和类型完全一致。内部实现只使用截止日已进入快照的财务和披露数据。

## 报告与索引

正式结果由两层组成：

- Markdown/JSON 文件保存完整正文、结构化输出、框架与数据边界，是事实来源。
- SQLite 报告索引保存检索字段，用于分页、搜索、筛选和对比，不取代原始报告。

报告阅读器先展示评分、建议、信心、核心逻辑、关键风险和章节目录，再按需展开正文与算子证据链。对比只允许同股票的时间变化，或同股票同日期的框架差异，避免比较无关对象。

## 页面组织

结构化投研工作区包含：

| 页面 | 任务 |
|---|---|
| 个股分析 | 选择对象和框架，查看章节级实时进度与结果 |
| 最新研判 | 预览并批量分析当前候选 |
| 框架验证 | 预览并执行历史截面验证，查看聚合结果 |
| 分析报告 | 分页检索、阅读和对比正式报告 |

每个页面有独立的投研助手上下文，切换页面不会清空历史。助手与人工操作同权复用现有 API；涉及修改的操作仍需通过结构化请求和用户确认。

策略通过 `operators_dir` 指定工作区内的版本。完整说明见 [v2 算子目录](../../workspace/operators/v2/README.md)。

## 非目标

- 不让 Agent 自由创建或改变正式研究流程。
- 不用当前资讯解释历史截面。
- 不把批量研判当成实盘组合或自动交易。
- 不因个别算子失败而静默生成“完整”结论。
